# Domain docs

Use the single-context layout: `CONTEXT.md` at the repo root and ADRs in `docs/adr/`.

Before exploring an area, read `CONTEXT.md` and relevant ADRs if they exist. Their absence requires no setup; the domain-modeling skill creates them when terms or decisions are resolved.

Use terms defined in `CONTEXT.md` for issue titles, proposals, hypotheses, and tests. If a concept is missing, reconsider the term or record the gap for domain modeling.

Surface any proposed change that conflicts with an ADR.
